当前进度：

- 豆包和元宝均已有 APK 无障碍自动输入、全文回读、单次发送、实时采集与自动回传的真机闭环；其余四平台尚未实现 APK 自动发题。

执行要求：

1. 先核实实际 serial、各 App 版本、signer、登录、网络、采集配置、无障碍 Bound/Crashed 状态、绑定地址、USB reverse 和当前 job/outbox。旧任务先按既有协议核对终态；未确认空闲前不派发、不安装、不跑 instrumentation。
2. 复用现有领取、准备、续租、任务关联、采集、持久化和幂等回传；按平台增加 UI 识别和动作适配，并同步包名监听、平台选择、就绪过滤及界面能力说明。不要只加 provider 字符串便宣布支持。
3. 完成当前平台适配、相关合成测试和必要构建／覆盖更新后，先做不发送预检：识别新会话、覆盖填写、回读全文、识别可用发送按钮，再清空草稿。生产发送依靠无障碍节点与状态核对，不使用固定坐标或模糊匹配。
4. 预检通过后，为当前平台创建一条新任务，冻结问题全文及 requestId。采集先就绪，APK 在点击发送前持久化 `send_started`；本任务只发送一次。结果不确定、重启、断线或租约失效后只收集和核对，不补发、不重新入队、不复活旧任务。该条验证失败时先保留证据、完成定位和可独立进行的修复；替代任务或再次发送需要另行说明原因并取得授权。
5. 保留原 CA、signer、登录、绑定和历史；更新抓包 APK 必须用原 signer 覆盖，并保留本机千问 ECH／UNet、文心缓冲等私有构建前提。先读当前私有构建入口并核对安装产物，不用普通构建覆盖后假设六平台仍可抓。
6. 网络条件按平台单独核实：豆包的 UDP443 策略、元宝 TLS 映射、千问私有条件、文心缓冲、Kimi Connect 原字节及独立推理，不统一套用某个平台设置。
7. 为新增状态和真实风险补合成测试，运行相关单测与必要构建。保留工作区已有改动；定位既有失败与本次回归，不通过删除测试或放宽语义绕过失败。
8. 验收必须证明 APK 自行输入与发送，电脑只用于开发、部署、创建任务和只读取证。唯一当前回答通过原完整性规则，手机与 GEO 的问题、原始正文、推理、来源、decoder、包名、session/exchange 等逐字段一致；原任务、job、批次终态及原回答详情均核对，不使用历史回答冒充本次结果。
9. 分开报告自动发题、完整采集、自动回传、长图生成、OSS 上传和原详情展示。没有实现的层次明确列为待完成；图片失败不改变已成功回答，也不触发重新发题。
10. 完成每个平台后更新公共交接及本机顶部最新记录，写明模式、版本、证据、限制、剩余事项和手机最终状态。测试结束暂停轮询、停止 VPN、关闭临时 ADB 导出，并确认无活动 job/outbox；保留用户原设置和账号材料，实际未恢复项明确记录。
