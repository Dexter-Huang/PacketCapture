# GEO 安卓设备工作台与调度接入

## 当前范围

手机已实现 HTTPS 设备绑定、主动领取、租约心跳、任务持久化、完整回答关联与幂等回传。GEO 继续管理监测配置、租户授权、回答槽位、计费和分析，手机不重复配置品牌或分析规则。

应用操作仍由人工完成：领取后先点击「准备本次采集」，复制任务原文，在目标应用的新对话中发送一次，再点击「核对完整回答并回传」。无障碍自动操作、自动提问、截图和无人值守后台调度尚未实现。跨 App 运行依赖本机进程和既有采集服务，不能据此宣称具备持续后台执行能力。

| 页面 | 实际功能 |
| --- | --- |
| 工作台 | 本机安装版本、连接和轮询状态、采集状态、平台样本范围 |
| 任务 | 凭据验证、继续/暂停轮询、当前问题、采集准备、回传、失败结束、终态核对与本地归档 |
| 采集 | 原实时请求、会话历史、详情、HAR 和回答 JSON 导出 |
| 设置 | HTTPS 根地址、设备名、10–300 秒空闲轮询间隔、计划平台及原采集设置 |

保存配置不代表已绑定。修改服务地址不会静默替换已绑定连接；无当前任务且轮询暂停时，可清除本机连接后重新绑定。服务端撤销凭据由 GEO 管理者操作。

领取还需同时满足：目标已安装、已选为抓包目标、HTTPS 采集运行中、平台目录为 verified_sample。不能据此推断当前登录、CA 信任和模式已就绪。文心依赖本地 CA 测试版与私有传输缓冲，已有失败诊断答案不会进入成功任务；千问实时解密仍受 [实测前提](../QIANWEN-CAPTURE-TEST.md) 限制。

## 立即监测入口

管理者先为指定监测签发设备凭据并在手机任务页绑定，再调用 `POST /api/android-rpa/v1/devices/{deviceId}/batches`，请求体为 `{"requestId":"持久化的唯一请求ID","provider":"kimi","repeatCount":1}`。provider 可选 deepseek、yuanbao、doubao、qianwen、wenxin、kimi，且须同时属于设备授权和监测配置；问题取监测的冻结快照，不由手机改写。响应中的 batchId 继续通过原品牌监测接口查询。

手机选择对应目标并启动 HTTPS 采集后，在任务页继续接单，准备采集并发送原文一次，仅唯一完整回答回传成功。相同 requestId 重试返回原批次；新一轮监测使用新 requestId。当前入口是新增安卓接口及手机任务页，GEO 网页管理入口、App 自动发题和长期后台执行尚未实现。六平台验证范围见本文末节及各平台实测文档。

## 已实现协议

新接口统一以 `/api/android-rpa/v1` 为前缀；原品牌监测和浏览器 HTTP 契约保持不变。当前没有绑定码或新 GEO 管理页面，管理者通过接口签发单监测设备凭据并派发批次。

| 方法与相对路径 | 身份与行为 |
| --- | --- |
| POST /devices | 管理者 JWT；传 monitorId/name/providers，201 返回一次性展示的 deviceId/deviceToken |
| GET /devices?monitorId=… | 管理者 JWT；列出可见监测的设备，不返回凭据 |
| DELETE /devices/{deviceId} | 管理者 JWT；撤销凭据，结束并结算未交付任务 |
| POST /devices/{deviceId}/batches | 管理者 JWT；传持久化 requestId/provider/repeatCount，返回原 batchId |
| POST /devices/heartbeat | 独立设备 Bearer；返回设备和绑定监测身份 |
| POST /tasks/claim | 设备 Bearer；传 requestId/providers，无任务为 `200 {"job":null}` |
| POST /tasks/{jobId}/heartbeat | 设备 Bearer 与 leaseToken；续租并返回任务 |
| PUT /tasks/{jobId}/result | 设备 Bearer；上传固定结果，只有 `{"accepted":true}` 才清除待回传记录 |

领取对象包含 jobId/batchId/taskId/provider/prompt/status/leaseToken/leaseUntil。jobId 为一次执行尝试，taskId 是原回答槽位；租约 180 秒，截止时间 UTC。每次重新校验发证用户、租户、监测和撤销状态。手机不能自行选择租户或执行服务器脚本。

派发与领取使用各自持久化幂等 ID；同一派发只创建、扣费一次，响应不确定时手机复用领取 ID 恢复同一任务。每台设备最多一个已领取任务。当前不接海外 Chat API 或指定提问位置。

## 持久化与失败处理

凭据、租约、领取 ID、任务、采集边界和待回传 JSON 整体通过 Android Keystore AES-GCM 加密，以 AtomicFile 存于不参与备份的目录。普通设置、ADB 回答接口和日志不导出令牌。

客户端仅连接绑定的 HTTPS 服务并拒绝重定向。公网使用系统证书校验；本地可显式固定服务端叶证书 SHA256，仍检查有效期和默认主机名，不关闭全部 TLS 校验。

1. 先保存领取 ID，再请求任务；收到后保存完整租约。
2. 准备采集先验证租约，再固定当前 sessionId 和设备时间起点，同一任务不能重复准备。
3. 问题人工发送一次；AnswerReader 精确匹配 provider、问题全文和时间边界。只有 unique_complete 能回传，缺失、歧义、失败和未知协议均保留诊断，不自动重发。
4. 先加密保存结果，再上传相同 JSON；响应丢失或进程重启后重试已有结果。重新打开 App 须点击继续接单，不自动恢复后台轮询。
5. 暂停轮询同时停止心跳，租约继续计时；有任务时心跳间隔最多 60 秒，空闲使用配置间隔。网络错误按该间隔重试，401/403/409/422 停止并保留记录；尚未实现指数退避和 Retry-After。
6. 过期任务按未交付失败退款，永不自动重新入队。目前由下一次设备心跳、领取、续租/回传或管理者撤销触发结算，没有独立离线清扫器，永久离线需管理者处理。
7. 终态核对返回同一个 jobId 且状态为 completed/failed/expired 后，才加密归档并清理本机活动记录，冲突不静默覆盖。

成功结果保留原始 answer、reasoning、searchSources、referenceCaptureStatus、decoder、工具版本、包名与 capture IDs。GEO 在原 resultJson 标记 source=android_capture_sse、executionChannel=android；collected 只说明取得来源 URL，不保证穷尽。不会默认上传 HAR、完整请求头、Cookie 或 CA 私钥。提及及后续分析复用原流程。

## 数据库与隔离

迁移 `20261019090000_android_brand_monitor_rpa` 只创建 android_rpa_devices、android_rpa_dispatches、android_rpa_jobs 三张表，不改旧字段或旧枚举。原批次构建内部增加默认开启的浏览器派发参数，仅新安卓接口关闭它并在同一事务创建手机队列，不生成 RpaChatTask；旧入口仍按原默认派发。

GEO 改动位于 codex/android-brand-monitor-rpa worktree，新迁移只应用到该 worktree 独立 MySQL，未连接旧数据库、未合并 GEO 主分支。共享环境应先执行 Prisma migrate deploy，再部署后端；绑定和派发须显式操作，默认不接管旧任务。
