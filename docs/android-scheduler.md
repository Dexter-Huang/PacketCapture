## 已实现协议

新接口统一以 `/api/android-rpa/v1` 为前缀。当前没有绑定码；GEO 管理页面和接口均限超管，新平台凭据不需要选择监测，旧显式 monitorId 仍兼容。

| 方法与相对路径 | 身份与行为 |
| --- | --- |
| POST /devices | 超管 JWT；传 name/providers，可选 monitorId 仅兼容专用范围，201 返回一次性展示的 deviceId/deviceToken |
| GET /devices | 超管 JWT；默认列出全部设备，可选 monitorId 过滤，不返回凭据 |
| PATCH /devices/{deviceId} | 超管 JWT；更新 name/providers/enabled，只影响新任务领取 |
| DELETE /devices/{deviceId} | 超管 JWT；撤销凭据，结束并结算该手机已分配的未交付任务 |
| POST /devices/{deviceId}/batches | 超管 JWT；传 requestId/provider/repeatCount，平台设备需 monitorId，返回原 batchId |
| POST /devices/heartbeat | 独立设备 Bearer；返回 deviceId，平台资源 monitorId 为 null，客户端只读取 deviceId |
| POST /tasks/claim | 设备 Bearer；传 requestId/providers，无任务为 `200 {"job":null}` |
| POST /tasks/{jobId}/heartbeat | 设备 Bearer 与 leaseToken；续租并返回任务 |
| PUT /tasks/{jobId}/result | 设备 Bearer；上传固定结果，只有 `{"accepted":true}` 才清除待回传记录 |

领取对象包含 jobId/batchId/taskId/provider/prompt/status/leaseToken/leaseUntil。jobId 为一次执行尝试，taskId 是原回答槽位；租约 180 秒，截止时间 UTC。每次重新校验发证用户、租户、监测和撤销状态。手机不能自行选择租户或执行服务器脚本。

派发与领取使用各自持久化幂等 ID；同一派发只创建、扣费一次，响应不确定时手机复用领取 ID 恢复同一任务。每台设备最多一个已领取任务。当前不接海外 Chat API 或指定提问位置。

## 持久化与失败处理

凭据、租约、领取 ID、任务、采集边界和待回传 JSON 整体通过 Android Keystore AES-GCM 加密，以 AtomicFile 存于不参与备份的目录。普通设置、ADB 回答接口和日志不导出令牌。

客户端仅连接绑定的 HTTPS 服务并拒绝重定向。公网使用系统证书校验；本地可显式固定服务端叶证书 SHA256，仍检查有效期和默认主机名，不关闭全部 TLS 校验。

1. 先保存领取 ID，再请求任务；收到后保存完整租约。
2. 领取或续租确认后自动准备，先固定当前 sessionId 和设备时间起点，再提示操作者发送；同一任务不重复准备，重启继续使用保存边界。
3. 自动模式仅领取选定平台任务；新任务才启用自动执行，旧任务保持人工模式。发送前加密保存 send_started 状态，然后重新核对输入原文并只点击一次；重启或点击结果不确定均不补发，4 分钟未完成则按原协议结束失败。默认关闭自动模式；平台支持及验收范围见本文顶部。AnswerReader 精确匹配 provider、问题全文和时间边界。重启采集后保留原始时间边界，并持久化记录后续就绪的采集会话；跨会话合并候选，重复候选仍判为歧义。只有 unique_complete 能回传，缺失、歧义、失败和未知协议均保留诊断，不自动重发。
4. 先加密保存结果，再上传相同 JSON；响应丢失或进程重启后重试已有结果。重新打开 App 须点击继续接单，不自动恢复后台轮询。
5. 暂停轮询同时停止心跳及自动回答检查，租约继续计时；有任务时心跳间隔最多 60 秒，空闲使用配置间隔。本地回答每 2.5 秒检查一次，不增加网络心跳频率。网络错误按配置间隔重试已保存结果，401/403/409/422 停止并保留记录；尚未实现指数退避和 Retry-After。
6. 过期任务按未交付失败退款，永不自动重新入队。GEO 主 worktree 增加既有监测同步调度中的离线租约清扫，部署后手机不回连也可结算；关闭服务端 RPA 调度时定期清扫停止。未领取的 queued 任务不因缺少手机超时。
7. 终态核对返回同一个 jobId 且状态为 completed/failed/expired 后，才加密归档并清理本机活动记录，冲突不静默覆盖。

只要轮询开启，尚未启动采集或没有适配平台时也发送设备心跳；领取、续租与结果回传同样刷新最近连接。GEO 统一以 360 秒通信窗口判定在线，网页每 30 秒刷新。在线只表示通信正常，不保证平台登录、采集就绪或 Android 长期保活。该心跳逻辑已随2026-10-21私有构建覆盖更新；豆包自动执行的验证范围见本文末节。

成功结果保留原始 answer、reasoning、searchSources、referenceCaptureStatus、decoder、工具版本、包名与 capture IDs。GEO 在原 resultJson 标记 source=android_capture_sse、executionChannel=android；collected 只说明取得来源 URL，不保证穷尽。不会默认上传 HAR、完整请求头、Cookie 或 CA 私钥。提及及后续分析复用原流程。
