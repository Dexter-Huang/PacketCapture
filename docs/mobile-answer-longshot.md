# 移动端回答长图：平台接入参考

## 2026-10-23 午后更新

六平台的本轮成功回答现已通过 Camofox 固定模板接口生成 `android-answer/2` 长图，上传私有 OSS，原详情与图片读取均 200；GEO 不再启动 Chromium。模板提取至 GEO `backend/geo_mobile_answer.py`，`android_answer_images.render_png` 调用 `POST /rpa/mobile-answer-images`，独立禁网络 Context 复用受控 Firefox。六平台限定模式的 APK 闭环已有证据，文心依赖私有真实 HTTP 完成缓冲；下表仍记录早期阶段，不再代表未通过平台清单。

用户明确同意复用 Camofox 并更新本机两个容器；真实图片、搜索摘要与各平台细节样式仍未完成，下方内容保真要求继续适用。完整实现、部署、测试与证据见 GEO `docs/handoff-mobile-brand-monitor-2026-10-23.md`。

更新：2026-10-22。本文是当前长图展示与平台接入约定；优先于 [早期离线原型交接](answer-long-image-handoff.md) 中的统一白底、960px、平台标题、说明脚注及暂不包含图片等旧建议。

## 1. 已确定的方案与实际进度

使用完整回答数据重新排版，尽量模仿对应 App 的聊天样式，浏览器对完整回答容器一次生成 PNG。生产流程不依赖手机原生滚动拼接，也不调用目标 App 的“分享回答／保存图片”。本机截图、UI 节点用于校准与取证，不等于实现了自动提取任意 App 样式。

用户已接受按平台维护近似样式，不要求 App 改版后立即自动一致。用户此前不希望采用服务端样式方案；本轮为查看效果而接受的本机预览，不代表已重新确认样式的最终部署位置。当前原型与已验证上传路径运行在 GEO，后续应先复用现有成果；将样式放入 APK、迁移出图位置或开放远端样式配置，属于尚未确定的架构调整。

| 层次 | 本轮事实 | 后续边界 |
| --- | --- | --- |
| APK 自动执行 | 豆包、元宝快速文本、DeepSeek 普通文本、千问快速模式已有闭环证据 | 文心已通过不发送预检、真机任务待验收；Kimi 执行器待实现。DeepSeek、千问图片失败单独保留，不重发 |
| 长图业务链路 | 一条豆包新任务的完整回答已自动生成旧版 PNG、上传私有 OSS、写入原任务图片字段，详情及图片读取均 HTTP 200 | 验证使用 `android-answer/1`，不是下列已确认新版样式 |
| 豆包样式 | 已确认手机宽度近似样式；本机预览包含原始字数文本、操作栏、两条实际追加建议 | 手机字体及追加建议目前由本机脚本提供，未自动采集回传 |
| 元宝样式 | 已确认浅色预览，包含引用图标、操作栏、来源角标和三条实际追加建议 | 本次较长搜索回答仍为 `unsupported`；只做视觉预览，没有上传、入库或将失败任务改为成功 |
| 搜索摘要 | 用户要求保留“搜索 X 个关键词、参考 X 篇资料”等实际提示 | 当前出图输入未实现完整采集与传递；不能用来源数组长度猜这些数字 |
| 回答图片 | 用户要求保留实际图片及位置、比例 | 当前服务端实现仍用图片占位；真实图片获取、可信资源交付与一致性验收待实现 |

元宝深色预览期间手机开启了深色模式；切换系统浅色后，实际 App 随之显示浅色，最终确认的是浅色预览。没有验证 App 的全部主题设置组合。

## 2. 内容与样式规则

| 元素 | 规则 |
| --- | --- |
| 问题 | 采用本任务冻结问题；按对应 App 的问题气泡排版 |
| 回答 | 保留正文顺序、标题、强调、列表、引用块、表格、代码及原始文本 |
| 字数文字 | `（全文296字）` 等若为模型原文，照常保留；不额外生成字数统计 |
| 额外标题／脚注 | 不增加“豆包 完整回答”、生成说明、采集说明、额外时间等文字；图片类型记录在元数据中 |
| 操作栏 | 包含 App 本轮实际存在的复制、赞踩、朗读、分享、重新生成等一行，按各平台实际顺序和样式，不统一套豆包图标 |
| 追加建议 | 保留本条回答对应的实际建议、顺序和换行；不存在则不生成，不能让模型补写 |
| 搜索摘要 | 有原始证据才展示，保留实际文案、数量和出现位置；没有证据不凑数、不显示假零值 |
| 引用与来源 | 原始 title/url/index 保留；只按已验证协议转换引用图标，不猜编号与来源映射。元宝本机图标是视觉示意，不是完整映射验收 |
| 图片 | 保留实际资源、正文位置、顺序、宽高比及有证据的裁剪方式；不换成相似生成图，不拉伸，不把视频或商品卡冒充正文图片 |
| 推理 | 默认不包含；需要时单独确定展示选项并纳入输入 hash |
| 手机外壳 | 不加入状态栏、固定输入框、系统导航、浮动按钮等覆盖正文的常驻界面 |

图片为 `answer_render`，不是原屏截图 `page_capture`；这种区分存入接口及任务元数据，无需在图片中添加用户已要求删除的说明小字。

### 宽度与换行

目标是同一设备和显示设置下尽量相同的换行，不是机械规定“每行 N 个字”。中英文、粗体、标点、emoji 和引用图标宽度不同。

1. 记录屏幕截图宽度、Android 逻辑密度、字体大小／显示缩放和 App 版本、主题。用逻辑宽度排版，用截图像素宽度导出。
2. 本轮手机样例为截图宽 1080px、逻辑密度 450dpi：`1080 / (450 / 160) = 384` CSS px，导出倍率 2.8125。这是本轮配置，不能作为所有设备的常量。
3. 校准正文左右内边距、字号、字重、字体、行高、段间距和标题间距，再核对相同段落的实际行尾。
4. 本机预览使用手机 MiSans 字体。正式工件需要明确可用字体及分发条件；不能依赖忽略目录里的字体必然存在，换字体后的预览需重新核对。
5. 浏览器和 Android 的文本排版可能有差异；当前仅做人工视觉校准，未验证逐行或逐像素完全相同。

## 3. 当前实现入口

路径相对各项目根目录；修改前分别阅读根 `AGENTS.md` 及对应约定。

| 仓库与路径 | 当前职责 |
| --- | --- |
| PacketCapture `app/src/main/java/com/packetcapture/execution/` | 无障碍界面识别和单次操作；后续 UI 展示元数据可在合适边界采集 |
| PacketCapture `app/src/main/java/com/packetcapture/scheduler/AndroidScheduler.kt` | 任务关联、采集、outbox 与回传；不为补图重新发题 |
| PacketCapture `llm/` | 完整回答语义及来源解码；增加字段前读架构与结果接口 |
| GEO `backend/app/services/android_rpa.py` | 接收完整回答，在原事务中登记 `answerImage` 待出图状态 |
| GEO `backend/app/services/android_answer_images.py` | `render_input`、`answer_html`、`render_png`、领取／完成图片工作及 `run_answer_image_once` |
| GEO `backend/app/rpa/service.py` | 既有品牌监测同步流程调用图片执行器；其调度关闭时不会自动消费图片任务 |
| GEO `backend/app/services/brand_monitor_screenshots.py` | 复用品牌监测私有 OSS 上传与授权读取 |
| GEO `backend/tests/test_android_answer_images.py` | 合成输入、身份、展示和 hash 验证；扩展图片能力时同步调整当前“阻断远端图片”用例 |

当前 GEO 源码为 `android-answer/2`，有手机宽度、豆包灰色回答块和固定操作栏；元宝专用浅色 CSS、手机字体、追加建议和来源角标仍在本机预览脚本，没有完整合入运行链路。运行进程是否加载最新源码需接手时核实。

当前 `render_input` 主要冻结 provider、prompt、answer、sources、jobId、模板版本、宽度、倍率及推理选项。现有公共回传没有正式实现下面建议的 `presentation` 字段。

## 4. 补齐展示数据

优先从当前实时响应的已验证结构提取；只在需要时从同一回答 UI 取实际显示值。语义字段归 `llm`，可见界面信息归执行／展示采集层，`capture` 保持只处理传输。

建议将展示信息作为版本化快照独立保存。以下为内部设计示意，字段名和公共 schema 均尚未实现，不能照此直接向当前接口上传：

```json
{
  "presentation": {
    "schemaVersion": 1,
    "provider": "synthetic_provider",
    "appVersion": "verified-version",
    "theme": "light",
    "viewport": {"cssWidth": 384, "pixelWidth": 1080},
    "searchSummary": {
      "text": "搜索2个关键词，参考8篇资料",
      "keywordCount": 2,
      "referenceCount": 8
    },
    "suggestions": ["实际建议一", "实际建议二"],
    "media": [
      {"id": "image-1", "anchor": "verified-block-id", "kind": "image",
       "assetKey": "tenant-scoped-private-object-key", "width": 800, "height": 600}
    ]
  }
}
```

上面的数字与建议仅是合成示意。实际值需附内部关联证据：当前 task/job、provider、session/exchange、回答身份及捕获时间。UI 信息可能晚于正文结束出现；设置有限等待，明确缺失状态，避免拿到上一条回答的建议或混入新会话。

`searchSources.length` 仅是已采集／去重 URL 数，不保证等于 App 的“参考篇数”；UI 中的关键词数也不从正文猜测。来源角标只使用真实已关联的资料，不把本机手工裁图当通用生产实现。

### 正文图片

实现顺序是“识别对应媒体块 → 取得同一资源 → 核对身份及尺寸 → 受控解码 → 作为内联或私有资源交给渲染器”。不能只给 Markdown 开放任意远程 URL 请求。

- 优先复用已经捕获且可关联的资源；带临时签名、鉴权或过期地址时，在授权边界内取得并保存实际图片，避免重新请求得到不同内容。
- 服务端补取资源时，单独做地址和重定向校验、目标 IP 校验、超时及下载／解码预算；拒绝内网、云元数据、本地文件与主动内容。记录资源摘要和原尺寸。
- 渲染上下文继续禁网。仅提供经过验证的图片字节，等待全部图片解码及字体完成后测量、截图；防止异步加载后裁掉页尾。
- 图片丢失、位置未知、尺寸错误时记录图片工作失败或明确降级范围，不把占位图称为“与 App 图片一致”。完整文本已保存的任务保持原状态，不触发重发问题。
- 当前真实预览没有覆盖含正文图片的回答；上线前需至少一份真实图片样本和合成异常资源测试。

## 5. 生成、上传与恢复

当前路径：APK 唯一完整回答 → GEO 提交回答并登记 `pending` → 既有同步器领取 → 浏览器生成 PNG → 私有 OSS → 原任务 `final_screenshot_object_key` 与 `answerImage` 状态。

- 回答事务／数据库锁外执行浏览器和 OSS；图片失败不改变完整回答、扣费、任务终态和安卓发送记录。
- 当前图片状态 `pending/rendering/ready/failed` 持久化，3 分钟图片租约、最多 3 次尝试，失败间隔 30 秒；不要把图片租约与手机任务租约混用。
- 输入 hash 覆盖所有实际展示内容和选项。新增主题、宽度、建议、搜索摘要、资源摘要或字体／模板版本时一并冻结，防止重试生成不同内容却复用同一对象键。
- 写回前再次核对租户、任务、androidJob、回答 hash 和图片 claim；不自动覆盖已有网页截图或批量补历史回答。
- 当前实现处理预算 40 秒、DOM 上限 12000、PNG 上限 10 MiB、总像素上限 4000 万。当前高度测量限制为 CSS 24000，不能写成已实现输出 PNG 高度 24000；正式整理时按输出像素再核对尺寸上限。

当前已通过的是 **GEO 服务端上传 OSS**；安卓通过 STS 直传没有实现、没有验收。只有决定在手机生成图片时才需要考虑设备级 STS 接口、租户对象范围、临时有效期和幂等完成确认；不要向 APK 下发长期 OSS 密钥。

## 6. 新平台接入步骤与完成条件

1. **基线**：阅读 [执行器交接](android-executor-handoff.md)、[手机调度](android-scheduler.md)、平台实测与本机 HANDOFF，核实设备、版本、CA、当前任务和采集前提。完成条件：基线可回查，没有不明活动任务。
2. **语义**：先复用已保存样本确认原始回答、来源和完成判断。新协议类型按真实结构分类：纯元数据可有针对性支持，未知正文变化仍拒绝完成。完成条件：严格完整性通过，并保留失败样本的真实状态。
3. **取样**：对同一回答保存首段、正文格式、搜索摘要、末尾操作栏、追加建议和媒体的实际界面参考；不为样式反复发题。完成条件：各可见元素均有来源或明确缺失。
4. **版式**：增加该平台样式，复用统一 Markdown／资源／截图流程；校准主题、字体、正文宽度、换行和图标顺序。完成条件：本机 PNG 首尾完整、无横向裁切，用户可查看。
5. **补齐快照**：正式实现需要展示的新字段及关联校验，并纳入持久化与 hash。完成条件：无需本机手工填写建议、计数或裁切来源角标即可复现同一张图。
6. **业务验收**：当前任务唯一完整回答，APK 自行输入与发送，GEO 原答案一致；自动生成图片、OSS 可授权读取，原详情展示成功。完成条件：分别记录自动发题、完整采集、回传、出图、上传、展示的结果；本机预览不能替代后四项。
7. **收尾**：停止测试轮询／VPN并关闭临时导出，核实无活动 job/outbox；保留 CA、signer、登录和历史，记录未恢复的用户设置。更新支持范围及本机交接，不扩大到未测模式。

单元测试只使用合成数据；真实截图、回答、HAR、资源链接和签名材料放忽略目录。建议覆盖手机宽度中英混排、不同字重、emoji、表格、真实引用标记清理、建议延迟、图片失效／超限、首尾完整、输入 hash 和图片重试不重发问题。
